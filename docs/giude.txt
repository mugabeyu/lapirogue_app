# PART 2 – FLUTTER GUEST MOBILE APPLICATION IMPLEMENTATION REQUIREMENTS

The Hotel Management System (Part 1) has already been completed using Next.js and Supabase.

The objective of Part 2 is to develop a Flutter Mobile Application for hotel guests. The mobile application must integrate directly with the existing Supabase database and follow the same architecture used throughout the system.

---

# IMPORTANT AUTHENTICATION REQUIREMENT

Guests must NOT exist only as records inside the `guests` table.

Every guest who is expected to access the mobile application must also have a corresponding account inside Supabase Authentication (`auth.users`).

The system must therefore maintain:

1. A guest record in the `guests` table.
2. A user account in Supabase Authentication.
3. A relationship between the two through an `auth_id` field.

The `guests` table must contain:

```sql
auth_id UUID UNIQUE
```

The value of `auth_id` must always match the corresponding user's ID from Supabase Authentication.

Example:

```text
auth.users
---------------------------------
id: 8f45a112-xxxx-xxxx-xxxx
email: johnsmith@gmail.com

guests
---------------------------------
guest_id: G0001
first_name: John
last_name: Smith
auth_id: 8f45a112-xxxx-xxxx-xxxx
```

This ensures that every guest using the mobile application has a secure authenticated account.

---

# AUTOMATIC GUEST ACCOUNT CREATION

Guest accounts shall be created automatically.

Receptionists and administrators must never manually create passwords or authentication accounts.

When:

1. A guest is registered.
2. A reservation is created.
3. A room is assigned.

The system shall automatically:

### Step 1

Create the guest record.

### Step 2

Create a Supabase Authentication account.

### Step 3

Generate and store the `auth_id`.

### Step 4

Update the guest record with the generated `auth_id`.

### Step 5

Generate a temporary password.

Password Format:

```text
LastName + RoomNumber + "@lapirogue"
```

Example:

```text
Smith205@lapirogue
```

### Step 6

Send an automated email containing:

* Welcome message
* Mobile application information
* Login email
* Temporary password
* Instructions for first login

---

# FIRST LOGIN REQUIREMENT

When a guest logs in for the first time:

* Authentication shall be performed through Supabase Authentication.
* The guest shall be required to change the temporary password.
* Access to the application shall only be granted after a successful password change.

The mobile application shall include:

* Change Password
* Forgot Password
* Password Reset via Email
* Secure Logout

---

# SECURITY REQUIREMENTS

The system shall use Supabase Authentication and Row Level Security (RLS).

Guests shall only be able to access information associated with their own account.

All guest-related tables must be protected using RLS policies based on:

```sql
auth.uid() = auth_id
```

or equivalent guest ownership rules.

Guests must never be able to access:

* Other guest profiles
* Other guest reservations
* Other guest schedules
* Other guest payments
* Other guest messages
* Other guest feedback

# EXPECTED OUTCOME

The Flutter Mobile Application shall function as a secure guest self-service portal integrated with the existing Hotel Management System.

Each guest shall possess a valid Supabase Authentication account linked to their guest profile through the `auth_id` field, ensuring secure authentication, proper access control, and protection of guest data while providing real-time access to hotel services throughout their stay.
